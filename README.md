# QuizRoom

Квіз-платформа реального часу: ведучий запускає квіз на ноутбуці з проєктором, учасники заходять із телефонів за PIN-кодом або QR, відповідають на час і бачать таблицю лідерів. Навчальний проєкт на TypeScript: Express і Socket.IO на сервері, React на клієнті. Без бази даних і акаунтів: квізи лежать у JSON-файлі, ігри живуть у памʼяті сервера.

## Швидкий старт

Потрібні Node.js ≥ 22.12 і npm.

```bash
npm install
npm run dev
```

`npm run dev` запускає разом сервер (порт 3001) і клієнт у dev-режимі (порт 5173).

| Хто | Адреса |
|---|---|
| Ведучий (ноутбук) | http://localhost:5173/quizzes |
| Гравці (телефони) | `http://<IP ноутбука>:5173` — сервер друкує цю адресу під час старту |
| Перевірка сервера | http://localhost:3001/api/health → `{"ok":true}` |

Під час першого запуску сервер створює `server/data/quizzes.json` із двома демо-квізами.

## Режим одного порту

Для презентації зручніше один процес і одна адреса: сервер сам роздає зібраний клієнт.

```bash
npm run build
npm start
```

Ведучий відкриває `http://localhost:3001/quizzes`, гравці — `http://<IP ноутбука>:3001`. Якщо збірки немає, `npm start` працює лише як API і підказує виконати `npm run build`.

## Боти

Боти заповнюють кімнату «гравцями», а з `--autohost` самі проводять гру. Сервер має бути вже запущений.

```bash
npm run bots -- --autohost --lobby-wait 30     # створити кімнату, 30 с на вхід, далі гра йде сама
npm run bots -- --pin 123456 --count 12        # 12 ботів у кімнату, яку веде людина
npm run bots -- --help                         # усі прапорці
```

Боти відповідають випадково й не знають правильних відповідей. `--skip 0` — відповідають усі, `--skip 1` — ніхто.

## Як підключити телефони

1. Ноутбук і телефони — в одній мережі Wi-Fi.
2. Сервер під час старту друкує рядок `Гравці: http://192.168.x.x:…` — цю адресу відкривають телефони. Її ж містить QR-код у лобі.
3. Телефон не відкриває сторінку:
   - Wi-Fi університету часто ізолює пристрої один від одного. Роздайте інтернет із телефона й підключіть до цієї точки і ноутбук, і телефони гравців.
   - Фаєрвол macOS або Windows може блокувати вхідні підключення до Node. Під час першого запуску дозвольте їх.

## Команди

| Команда | Що робить |
|---|---|
| `npm run dev` | сервер :3001 і клієнт :5173 разом |
| `npm run build` | збірка клієнта в `client/dist` |
| `npm start` | сервер роздає зібраний клієнт на :3001 |
| `npm run bots -- …` | боти й авто-ведучий |
| `npm run typecheck` | перевірка типів у всіх пакетах |
| `npm test` | модульні тести |
| `npm run smoke` | наскрізний прогін сервера: сам піднімає його й грає через справжні сокети |

## Структура

```
shared/src/index.ts   контракт між сервером і клієнтом: типи, константи, валідація квізу
server/
  src/quiz/           JSON-сховище квізів і REST API
  src/game/           engine.ts — правила гри, views.ts — знімки стану,
                      sockets.ts — події Socket.IO і таймери
  scripts/            smoke-прогін і боти
client/               React-клієнт (Vite)
docs/                 план, контракт, сценарій демо
```

## Як це працює

1. **Сервер — єдине джерело правди.** Фаза гри, таймер, бали й місця існують лише на сервері. Клієнт нічого не рахує, тільки показує.
2. **Знімки замість подій.** Після будь-якої зміни сервер надсилає кожному учаснику повний знімок кімнати: ведучому — `host:state`, кожному гравцю — свій `player:state`. Пропустити подію й розсинхронізуватись неможливо: наступний знімок усе одно повний.
3. **Повторюваний вхід.** Сторінка гри надсилає `host:join` або `player:join` під час завантаження і після кожного перепідключення сокета. Оновлення сторінки, сон телефона й обрив мережі обробляє той самий код.
4. **Дедлайн, а не відлік.** Сервер не шле «залишилось N секунд». У знімку є час завершення питання `endsAt` і час сервера `serverNow`: клієнт сам малює відлік, а питання все одно закриває серверний таймер.

Правила гри зібрані в `server/src/game/engine.ts` як чисті функції — їх можна прочитати й протестувати без мережі.
